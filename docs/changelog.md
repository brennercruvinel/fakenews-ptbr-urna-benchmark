# Changelog

## Unreleased

- Pin Urna 0.5.4, the published release, instead of 0.5.1 (`pyproject.toml`, `uv.lock`) (#6). Nothing measured here changes: the benchmark calls `urna.build`, `search`, `search_ann` and `search_hybrid` from the Python API, which did not change from 0.5.1 to 0.5.4, and the potion table in the two wheels is byte-identical (same `model_hash`, `model.safetensors` and `tokenizer.json`). The v0.1 numbers keep the version that measured them: experiments 02 and 03 now say urna 0.5.1 in their provenance, as the build locks and experiment 04 already did, and `profiles/models.toml` keeps potion's `revision = "urna==0.5.1"`, the wheel the v0.1 builds used. `check_clean.sh` ran again with 0.5.4 (experiment 04).
- What Urna 0.5.4's renames broke here: the header image of the README and the card (`main/assets/images/`, 404) and the `chunk.rs` link (`crates/urna-format/`, 404) point at the v0.5.4 tag and the new paths. `docs/urna-gate.md` maps Urna as of 0.5.4 (`script/precommit`, `script/fullcheck.sh`, `Dockerfile`, `docs/ARC.toml`, the scripts 0.5.2 removed).
- The retrieval method said the files are searched the way the Urna CLI routes them, beam max(100, k). Urna 0.5.1 sent hybrid files down HNSW; 0.5.3 and later route them by what the file carries, which is what `evaluate.py` does, and the HNSW beam is widened to the file's floor of 400 (its `ef_construction`). The text says so; the numbers are the same.
- The README gave minilm recall@10 as 0.660; RESULTS renders 0.659 (0.6595), and the README follows it.
- Hub pull request #4, which this changelog had not listed: the card drops its Citation section; `CITATION.cff` is the citation.
